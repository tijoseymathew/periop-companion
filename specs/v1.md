# PeriOp Companion — Project Specification

**An agentic peri-operative documentation assistant for anesthesia providers, built on the NVIDIA Ambient Provider blueprint, orchestrated with Google ADK, instrumented and evaluated with NVIDIA NeMo Agent Toolkit, and grounded in Singapore demographics via Nemotron-Personas-Singapore.**

Version: 0.1 (draft for review)
Status: Reference/demonstration project — all data synthetic, no PHI. Documentation-support tool only; not a medical device and not a clinical decision-making system.

---

## 1. Problem statement

Anesthesia documentation is fragmented across three phases with different capture modalities and different consumers:

1. **Pre-op**: The pre-anesthesia evaluation depends on prior records that are frequently incomplete or stale, and on a patient interview where patients often cannot recall medications, prior anesthetic events (e.g., difficult airway, PONV), or comorbidity details. Providers reconstruct this under time pressure.
2. **Intra-op**: The anesthetist's hands and eyes are occupied. Events (induction agents, doses, times, airway management, lines, fluids, hemodynamic events) are documented retrospectively or in fragments, with known accuracy and completeness problems.
3. **Post-op**: The PACU handoff must compress pre-op history, intra-op course, and anticipated issues into a structured, high-stakes verbal + written transfer. Handoff omissions are a recognized patient-safety failure mode.

The common thread: **the source of truth is scattered across documents and audio**, and every downstream artifact (pre-anesthesia note, intra-op record, PACU handoff) is a synthesis whose trustworthiness depends on being able to trace each statement back to its source. Clinicians will not trust — and regulators (especially in sovereign/government health contexts) will not accept — generated notes that cannot show their work.

**PeriOp Companion** is a multi-agent application that follows the patient through all three phases, generating stage-appropriate documentation where **every claim in every generated note carries provenance** to either a source record chunk or a timestamped, diarized audio segment.

### Design rationale

- The project **extends** (not merely re-skins) the [ambient-provider](https://github.com/NVIDIA-AI-Blueprints/ambient-provider) blueprint: from single-encounter transcription → note, to a stateful, multi-stage, multi-agent longitudinal workflow with cross-stage memory and provenance.
- It exercises the full NVIDIA stack: NIMs (ASR + LLM + TTS), Nemotron models, NeMo Agent Toolkit (tracing, profiling, eval), NeMo Data Designer-style synthetic data, and the NVIDIA/skills catalog.
- Sovereign AI: synthetic patients are drawn from Nemotron-Personas-Singapore (co-designed with AI Singapore), demonstrating locally grounded, privacy-preserving evaluation — the same pattern applicable to broader government/citizen-services workflows.
- Gold-standard outputs are validated by a practicing anesthetist (SME), so evaluation is anchored to clinical judgment rather than LLM self-assessment alone.

## 2. Scope

### In scope (MVP)
- Three stage-workflows (pre-op, intra-op, post-op) runnable end-to-end on synthetic data.
- Claims-based provenance ledger spanning documents and audio.
- Synthetic data pipeline: personas → patient profiles → scripted encounters → TTS audio → gold notes.
- NAT-instrumented tracing, profiling, and an eval harness with provenance-accuracy metrics.
- CLI + minimal review UI (reuse/adapt the blueprint's React frontend or NAT UI).

### Out of scope
- Real patient data, EHR integration (FHIR adapters noted as future work).
- Real-time bedside deployment, medical-device claims, drug-dose validation/alerting logic.
- Fine-tuning (noted as flywheel future work using the eval dataset).

## 3. Architecture

### 3.1 Layering

```
┌─────────────────────────────────────────────────────────────┐
│  Review UI (adapted ambient-provider React app / NAT UI)    │
├─────────────────────────────────────────────────────────────┤
│  NeMo Agent Toolkit (nvidia-nat[adk] + [profiler] + [opentelemetry])
│  • run/serve/eval CLI  • OTel traces  • token & latency profiles
│  • eval harness (custom provenance evaluators)               │
├─────────────────────────────────────────────────────────────┤
│  Google ADK — agent orchestration                            │
│  • Stage pipelines as SequentialAgent/LlmAgent compositions  │
│  • Session state = the Case object (longitudinal memory)     │
│  • Tools: transcribe, chunk_records, claim_extract, ...      │
├─────────────────────────────────────────────────────────────┤
│  NVIDIA NIMs (hosted via build.nvidia.com by default)        │
│  • ASR: Parakeet 1.1B + Silero VAD + Sortformer diarization  │
│  • Reasoning LLM: llama-3.3-nemotron-super-49b-v1.5          │
│  • Fast LLM: nemotron-nano (cheap extraction/classification) │
│  • TTS (synthetic data only): Magpie TTS multilingual        │
├─────────────────────────────────────────────────────────────┤
│  Storage: local JSON/SQLite case store + audio artifacts     │
└─────────────────────────────────────────────────────────────┘
```

Design rule: **ADK owns orchestration, NAT owns observability and evaluation.** ADK agents are registered as NAT functions via the `nvidia-nat[adk]` plugin so the whole workflow is drivable by `nat run / nat serve / nat eval` and every LLM/tool call lands in the NAT profiler and OTel exporters. (Note: NAT 1.8 documents ADK as a supported framework; check the framework-support matrix for the exact tracing depth and pin `nvidia-nat~=1.8` — the ADK extra conflicts with a few other extras such as `openpipe-art`.)

### 3.2 The Case object (shared state)

A single `Case` persists across stages and is the substrate for provenance:

```jsonc
{
  "case_id": "sg-0042",
  "patient_profile_ref": "personas/uuid…",        // synthetic only
  "sources": [                                     // append-only registry
    {"source_id": "doc:gp-summary-2024", "type": "document", "chunks": [...]},
    {"source_id": "doc:op-plan", "type": "document", "chunks": [...]},
    {"source_id": "audio:preop-interview", "type": "audio",
     "segments": [{"seg_id": "s017", "t0": 214.3, "t1": 221.8,
                   "speaker": "PATIENT", "text": "…stopped the aspirin last Tuesday…"}]}
  ],
  "artifacts": [                                   // generated outputs
    {"artifact_id": "note:pre-anesthesia-eval", "claims": [
       {"claim_id": "c-031",
        "text": "Aspirin was discontinued 6 days prior to surgery.",
        "provenance": ["audio:preop-interview#s017"],
        "status": "supported"}                     // supported | unsupported | conflicting
    ]}
  ],
  "open_questions": [...],                          // pre-op gap analysis output
  "anticipated_issues": [...]                       // carried intra-op → post-op
}
```

Every generated note is stored **as a set of claims**, and the rendered document is assembled from claims — so provenance is structural, not a post-hoc annotation. Conflicts (record says X, patient says Y) are first-class: flagged, never silently resolved.

### 3.3 Stage 1 — Pre-op

| Step | Agent / Tool | Model | Input → Output |
|---|---|---|---|
| 1 | `RecordIngestor` (tool) | — | Prior notes + op plan → structured, chunked sources with stable chunk IDs. **No vector embeddings/RAG**: documents are small enough to fit in context; chunking exists purely to give provenance links stable, citable anchors (deterministic section/paragraph chunking) |
| 2 | `GapAnalyst` (LlmAgent) | Nemotron Super 49B (reasoning) | Sources → prioritized clarification questions, each tagged with *why* (missing / stale / conflicting) and provenance to the triggering chunk |
| 3 | Provider Q&A (optional HITL) | ADK human-in-the-loop | Provider edits/approves question list |
| 4 | `InterviewTranscriber` (tool) | Parakeet NIM (offline + Sortformer diarization) | Interview audio → diarized, timestamped transcript with speaker roles mapped (PROVIDER/PATIENT/CAREGIVER) |
| 5 | `PreOpNoteWriter` (LlmAgent) | Nemotron Super 49B | Sources + transcript + question/answer alignment → **pre-anesthesia evaluation note** structured per ASA elements (history, meds/allergies, NPO, airway exam findings as dictated, ASA-PS with justification-as-claims, plan) |

The question→answer alignment step is the interesting agentic behavior: each generated question is linked to the transcript segments that answered it (or marked unanswered → residual risk list).

### 3.4 Stage 2 — Intra-op

| Step | Agent / Tool | Model | Input → Output |
|---|---|---|---|
| 1 | `VoiceNoteTranscriber` | Parakeet NIM, **streaming** profile, with word boosting for an anesthesia lexicon (propofol, rocuronium, sugammadex, phenylephrine, LMA, RSI…) | Anesthetist voice notes → timestamped transcript |
| 2 | `EventExtractor` (LlmAgent) | Nemotron Nano first pass → Super 49B verification | Transcript → structured events: `{t, category: agent|dose|airway|line|fluid|event, value, units, provenance}` against a strict JSON schema |
| 3 | `IntraOpRecordWriter` | Super 49B | Events → chronological intra-op record (agents/doses/times, airway, lines, fluids, notable events) |
| 4 | `IssueAnticipator` (LlmAgent) | Super 49B | Pre-op note + intra-op events → anticipated post-op issues (e.g., PONV risk given history + volatile use; airway watch given grade-3 view), each a claim with provenance to *both* stages |

### 3.5 Stage 3 — Post-op

| Step | Agent / Tool | Output |
|---|---|---|
| 1 | `PostOpTranscriber` | Diarized post-op interview transcript |
| 2 | `HandoffComposer` | **PACU handoff** (e.g., SBAR-shaped): pre-op summary + intra-op course + anticipated issues — assembled *only from existing claims* (composition, not new generation → provenance is inherited) |
| 3 | `PostAnesthesiaEvaluator` | Post-anesthesia evaluation note from the post-op interview + case history |

The HandoffComposer is deliberately constrained: it may select, order, and lightly rephrase claims but may not introduce new claims. This is a clean, demoable statement about hallucination control in agentic pipelines.

## 4. Provenance & explainability design

1. **Claim decomposition**: every generated note is decomposed (by the writer agent itself, emitting structured output) into atomic claims.
2. **Provenance links**: each claim references ≥1 `source_id#chunk/segment`. Audio provenance carries `(t0, t1, speaker)` so the UI can play the exact clip.
3. **Verification pass**: a separate `ClaimVerifier` agent (Nemotron Nano, NLI-style prompt) re-checks each claim against its cited spans → `supported / unsupported / conflicting`. Unsupported claims are surfaced in the UI, never silently kept.
4. **UI affordance**: adapt the blueprint's existing citation-in-editor feature — click a sentence → highlight source chunk or play audio segment.
5. **Trace-level explainability**: NAT OTel traces (exportable to Phoenix/Weave) show which agent, prompt, and model produced each artifact — provenance for the *process*, complementing provenance for the *content*.

## 5. Synthetic data pipeline (Sovereign AI grounding)

No real patients. Pipeline:

```
Nemotron-Personas-Singapore ──filter/sample──► Patient profile
        (healthcare_persona + age/sex/ethnicity/occupation/…)
                │
                ▼
CaseDesigner (Super 49B): assign surgery type + plausible comorbidity
bundle + medication list + a deliberate "documentation defect"
(missing allergy, stale med list, or record/patient conflict)
+ **distractor history**: resolved/irrelevant items (e.g., pneumonia
cleared years ago, remote fracture, discontinued meds) so records are
realistically noisy — agents must weigh relevance, not just extract,
and the eval can penalize distractors surfacing in notes/handoffs
                │
                ├──► Prior-records pack (GP summary, med list, old anesthetic record)
                ├──► Scripted pre-op interview (diarized gold transcript,
                │        colloquial Singapore-English register from persona)
                ├──► Scripted intra-op voice notes + post-op interview
                └──► GOLD artifacts: pre-anesthesia note, intra-op record,
                     PACU handoff — with gold claim/provenance annotations
                │
                ▼
Magpie TTS NIM ──► audio renditions of interview scripts (multi-speaker
via per-speaker synthesis + concatenation) → exercises the real ASR path
                │
                ▼
SME validation: anesthetist reviews ~10 cases for clinical plausibility
and gold-note correctness (documented as a validation memo in the repo)
```

Notes:
- The dataset card lists a `healthcare_persona` field plus demographic/contextual fields grounded in the 2024 Singapore census — sample stratified across age bands and ethnicities so the eval set reflects the population the system would actually serve (the core sovereign-AI evaluation argument).
- The deliberate documentation defects are what make the GapAnalyst evaluable: gold = "these questions should have been asked."
- Target: ~30 generated cases; 10 SME-validated; 20 model-validated (LLM-judge cross-check).
- Verify the current TTS model name/voices on build.nvidia.com at build time (speech NIM catalogs move fast); the `nemotron-speech` skill in NVIDIA/skills is the reference for current model/function IDs.

## 6. Evaluation (NAT eval harness)

Run via `nat eval` with an `eval_config.yml` superset of the workflow config. Dataset = the synthetic cases above (inputs + gold artifacts).

**Metrics (custom NAT evaluators unless noted):**

| Metric | Definition |
|---|---|
| Provenance precision | Of claims with citations, fraction whose cited span actually entails the claim (LLM-judge NLI, spot-checked by SME) |
| Provenance recall / coverage | Fraction of claims in the generated note carrying ≥1 valid citation |
| Claim recall vs gold | Fraction of gold claims present in the generated note (the "did it miss the allergy" metric) |
| Hallucinated-claim rate | Claims not entailed by any source (target: ~0 for HandoffComposer by construction) |
| Gap-analysis quality | P/R of generated pre-op questions vs gold question set (defect-driven) |
| Clinical term ASR accuracy | Keyword Error Rate over the anesthesia lexicon (pattern from the `digital-health-clinical-asr-*` skills in NVIDIA/skills), with/without word boosting |
| Distractor leakage | Rate at which gold-labeled irrelevant history items (e.g., long-resolved pneumonia) appear in generated notes/handoffs without justification — measures relevance judgment, not just extraction fidelity |
| Structured extraction F1 | Intra-op events vs gold event log (exact-match on agent/dose/route/time bucket) |
| Cost/latency | NAT profiler: per-stage token usage, per-agent latency, bottleneck analysis; include one profiler screenshot/report in the README |

**A/B experiments the harness enables:**
- Word boosting on/off → KER delta on drug names.
- Nemotron Nano vs Super 49B for extraction → quality/cost/latency trade-off from the profiler.
- Composer-constrained vs free-generation handoff → hallucinated-claim rate delta.

## 8. Model & service selection

| Function | Default (hosted, build.nvidia.com) | Rationale |
|---|---|---|
| ASR + diarization | `parakeet-1.1b-en-US` NIM w/ Silero VAD + Sortformer (offline for interviews, streaming for intra-op) | Same stack as the blueprint; diarization is essential for interview provenance |
| Note generation / reasoning | `nvidia/llama-3.3-nemotron-super-49b-v1.5` | Blueprint's reasoning model; strong structured generation |
| Cheap extraction / verification | `nvidia/nemotron-nano-…` (current nano on catalog) | Cost/latency; showcases model-tiering, measurable in profiler |
| Synthetic-audio TTS | Magpie TTS NIM (verify current ID) | Closes the loop so real ASR is exercised |
| Orchestration | Google ADK (`google-adk`) | Lightweight, composable agent pipelines; officially supported NAT framework |
| Instrumentation/eval | `nvidia-nat[adk,profiler,opentelemetry]` ~=1.8 | Tracing, profiling, eval, `nat serve` |

Environment: single `NVIDIA_API_KEY`; no GPU required for the default path — anyone can clone and run with just an API key.

### 8.1 Self-hosted NIM endpoints (implemented — M6)

The same code runs against locally deployed NIMs; endpoint selection is purely environment-driven, so no call site changes between hosted and local runs:

| Variable | Meaning |
|---|---|
| `PERIOP_NIM_BASE_URL` | OpenAI-compatible base URL for both LLM tiers |
| `PERIOP_REASONING_BASE_URL` / `PERIOP_FAST_BASE_URL` | Per-tier overrides (win over the generic) |
| `PERIOP_REASONING_MODEL` / `PERIOP_FAST_MODEL` | Served-model name overrides |
| `PERIOP_ASR_BASE_URL` / `PERIOP_TTS_BASE_URL` | Speech NIM HTTP endpoints (Parakeet / Magpie) |

`NGC_API_KEY` is required only for the hosted endpoint — local NIMs don't authenticate. `configs/selfhosted.env` holds a sourceable endpoint set; `configs/selfhosted.yml` is the matching `nat run` config.

**Reference deployment** (single local GPU box — deployable locally, fully sovereign): all four NIMs co-tenant via docker compose — Super 49B (`:8000`, KV cache capped at 30%), Nemotron Nano 9B (`:8001`, KV 15%, **arch-specific image variant** — a generic tag can ship a mismatched architecture and crash-loop), Parakeet ASR (`:9000`), Magpie TTS (`:9001`). Models cache to a shared host volume; bring-up is sequential, heaviest first. This replaces the earlier "2×H100/4×A100" sizing guess: the whole stack fits one local GPU box when KV caches are bounded.

## 10. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Diarization confuses provider/patient | Role-mapping heuristic (provider asks the generated questions → anchor speaker identity); scripts designed with clear turn-taking; degrade gracefully to speaker-agnostic provenance |
| TTS audio too clean → ASR results unrealistically good | Optional noise/room-IR augmentation pass; report KER both ways |
| Drug/dose extraction errors look clinically dangerous | Strict schema + verifier pass + prominent "documentation aid, human review required" framing everywhere; never generate dosing *recommendations* |
| NAT↔ADK integration friction (young plugin) | Fallback: run ADK natively, use NAT for eval/profiling only via function wrappers — architecture keeps the seam narrow |
| Scope blow-up | HandoffComposer and eval harness are the differentiators; UI polish is last |
| Model/catalog drift (NIM IDs, TTS voices) | Pin versions; verify IDs on build.nvidia.com at build time; note in README |
